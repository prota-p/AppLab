## なぜ測り直したか

**2026-08-29 のログは削除しました。記事の根拠はこのログだけです。**
当時のシステムプロンプトに、**サンプルデータの答えそのものが例として書いてあった**ためです。
汚染された条件で取った数値を残しておくと、どちらが根拠か分からなくなります
（旧ログの内容が必要になったら `git log` から取り出せます）。

| プロンプトの記述 | サンプルデータ | 当たっていた依頼 |
|---|---|---|
| `例:「クラウド」を除くなら クラウド・Azure・AWS・GCP なども一緒に入れる` | 佐藤・岡田の紹介文が `Azure` | **依頼D** |
| `例:「組込」と「組み込み」の両方` | 加藤 `組込み` / 村上 `組み込み` | **依頼A** |
| `例:「サーバー」ではなく「サーバ」` | 井上 `サーバー` / 岡田 `サーバ` | （依頼にはないが図の教材と同一） |
| `例:「C」は React や CISSP にも当たってしまう` | 鈴木 `React` / 中村 `CISSP` | （同上） |
| 出力例 `{"include": ["C#", "バックエンド"]}` | 佐藤・加藤 `C#` / 佐藤・松本 `バックエンド` | （同上） |

これでは「規則が効いた」ではなく「答えを教えたから当たった」を測っていることになります。
**プロンプトに書いてよいのは、照合の性質から導ける一般的な規則だけ**とし、
サンプルデータに実在する語は規則の例からも出力例からも外して、**全51回を測り直しました。**

差し替えた例は、いずれもサンプルデータに1文字も出てこない語です。

| 規則 | 旧の例 | 新の例 |
|---|---|---|
| 概念を製品名へ展開 | クラウド → Azure・AWS・GCP | BIツール → Tableau・Power BI・Looker |
| 語中の送り仮名 | 組込 / 組み込み | 申込 / 申し込み |
| 末尾の長音 | サーバー / サーバ | フォルダー / フォルダ |
| 英数字1文字 | C は React や CISSP に当たる | C は Cookie や CI に当たる |
| 出力例 | `["C#", "バックエンド"]` | `["含めたい語"], ["除きたい語"]`（全版で統一） |

`rag.txt` の「ないことを探す依頼」の記述も、依頼Dの文言に寄っていたため一般化しました
（`「〜の経験がない人」のように` → `あることではなく`）。人名・技術名は元から入っていません。
